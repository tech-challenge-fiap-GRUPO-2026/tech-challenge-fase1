Pré-processamento e Engenharia de Features

Estratégias adotadas para tratar valores faltantes, reduzir redundância e criar features úteis.

  • Leitura com tratamento de valores faltantes
    O dataset foi lido novamente usando na_values='?', convertendo todos os pontos de interrogação para NaN do Pandas — facilitando as operações estatísticas subsequentes.
  • Indicadores de Missing (Missing Indicators)
    Para cada coluna com dados faltantes, foi criada uma nova coluna binária (_preenchido: 1 = respondeu, 0 = não respondeu). Isso preserva a informação de que a paciente se recusou a responder, o que pode ser um sinal estatisticamente relevante. A coluna original foi então imputada com a média.
  • Agrupamento de colunas indicadoras redundantes
    Foi verificado que várias colunas _preenchido tinham exatamente os mesmos valores (ex.: todas as variáveis de DST tinham 87,76% de respostas válidas). Essas colunas duplicadas foram consolidadas em uma única coluna representativa por grupo.
  • Feature Engineering — Tabagismo
    As colunas Smokes (years) e Smokes (packs/year) foram multiplicadas criando smoke_year_packs (exposição acumulada ao tabaco). Antes, foi garantida a consistência: se Smokes = 0, os outros campos também foram zerados.
  • Consistência dos Contraceptivos
    Se Hormonal Contraceptives = 0, então Hormonal Contraceptives (years) também foi zerado para evitar inconsistências nos dados.
  • Remoção de colunas sem variabilidade
    STDs:AIDS e STDs:cervical condylomatosis foram removidas por conter apenas zeros em todos os 858 registros.

Visão Geral — Grupos de Missing Indicators Criados

✅
Por que usar a média + indicador de missing? Simplesmente remover linhas com dados faltantes reduziria muito o tamanho do dataset (já pequeno com 858 amostras). Usar apenas a média "apagaria" a informação de recusa. A combinação média + coluna indicadora permite ao modelo aprender tanto o valor imputado quanto o comportamento de não-resposta — uma abordagem mais rica.

Modelagem — Random Forest Baseline

🌲
O que é Random Forest? Random Forest é um algoritmo de aprendizado de máquina baseado em múltiplas Árvores de Decisão treinadas em amostras e features aleatórias do conjunto de treino. A predição final é a votação majoritária entre todas as árvores. É robusto a overfitting, lida bem com dados mistos e é difícil de bater em conjuntos de dados tabulares de tamanho moderado.

🔴
O problema do Recall baixo na classe positiva Um Recall de apenas 9% na classe positiva significa que o modelo identificou corretamente apenas 1 de cada 11 casos reais de câncer no conjunto de teste. Isso é crítico em aplicações médicas: falsos negativos (perder um caso de câncer) são muito mais perigosos que falsos positivos (alarmes desnecessários). O alto class_weight ajudou parcialmente, mas o dataset pequeno e muito desbalanceado limita o desempenho.

Modelagem — Transfer Learning com Exames Auxiliares

🧠
O que é Transfer Learning neste contexto? Transfer Learning (aprendizado por transferência) normalmente é usado em Deep Learning para aproveitar pesos de redes pré-treinadas. Aqui, a abordagem foi adaptada para dados tabulares: treinar modelos auxiliares nos outros exames (Hinselmann, Schiller, Citologia) e usar as probabilidades preditas como novas features para o modelo final de Biópsia. A intuição é que esses exames clínicos compartilham fatores de risco comuns.

🤔
Por que o Transfer Learning não melhorou? O resultado idêntico entre os dois modelos pode ser explicado por:
  • O dataset é muito pequeno (858 amostras, apenas 11 positivos no teste);
  • Os modelos auxiliares já utilizavam as mesmas features originais, então a informação adicionada é redundante;
  • Com apenas 11 positivos no conjunto de teste, qualquer variação de 1–2 casos muda completamente as métricas;
  • O Random Forest Baseline já era capaz de explorar as correlações entre as variáveis internas.

Discussão e Conclusões

7.1 — Discussão da Análise Exploratória

📈
O dataset apresenta perfil de pacientes jovens (média 26,8 anos), com baixa prevalência de DSTs e tabagismo. O principal desafio identificado foi o desbalanceamento extremo das classes alvo: a Biópsia positiva representa apenas 6,4% dos casos. As altas taxas de dados faltantes em variáveis sensíveis (DSTs, contraceptivos) sugerem que a privacidade impactou a qualidade dos dados coletados.

7.2 — Estratégias de Pré-processamento

⚙️
A imputação por média combinada com indicadores de missing preserva a informação de comportamento de não-resposta. A engenharia da feature smoke_year_packs agrega a exposição cumulativa ao tabaco de forma mais informativa. A remoção de variáveis sem variabilidade evita ruído no modelo.

7.3 — Modelos Utilizados e Por Quê

ModeloJustificativa
Random Forest (Baseline) Robusto a outliers e variáveis irrelevantes. Suporta dados mistos (binários + contínuos). O parâmetro class_weight compensa o desbalanceamento sem precisar de oversampling.
Transfer Learning (RF Auxiliares) Abordagem inovadora para dados tabulares: aproveita o sinal clínico de exames correlatos (Hinselmann, Schiller, Citologia) para enriquecer as features do modelo principal (Biópsia). Justificada pela correlação clínica entre os exames.

7.4 — Resultados e Interpretação

⚠️
Alta Acurácia ≠ Bom Modelo para Triagem Médica O modelo atingiu 94% de acurácia — mas isso é enganoso. Como apenas 6,4% dos casos são positivos, um modelo que nunca prediz positivo já acerta 93,6% das vezes. O verdadeiro problema está no Recall de 9% para a classe positiva: o modelo perde 91% dos casos reais de câncer, o que é inaceitável para triagem clínica.
💡
O que melhoraria os resultados?
  • Técnicas de oversampling (SMOTE) para balancear as classes;
  • Ajuste do threshold de decisão (por ex. usar probabilidade > 0.3 em vez de > 0.5);
  • Mais dados — 858 amostras com 55 positivos é muito limitado;
  • Otimização de hiperparâmetros com GridSearchCV ou Optuna;
  • Avaliação por AUC-ROC e Curva Precisão-Recall em vez de acurácia.
