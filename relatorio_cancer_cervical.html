Pré-processamento e Engenharia de Features

⚙️
Pipeline sklearn encapsulado Todo o pré-processamento foi encapsulado em um imblearn.pipeline.Pipeline, garantindo que as mesmas transformações sejam aplicadas no treino e no teste, sem vazamento de dados (data leakage).
  • Remoção de colunas sem variabilidade
    STDs:AIDS e STDs:cervical condylomatosis removidas — 858 valores iguais a zero, zero variância.
  • Tratamento de valores nulos + Missing Indicators
    Para cada coluna com NaN: criada coluna _preenchido (1 = respondeu, 0 = não respondeu) e valores nulos substituídos pela média. A informação de recusa é estatisticamente relevante e preservada.
  • Agrupamento de colunas indicadoras idênticas
    Colunas com exatamente o mesmo padrão de resposta (ex.: todas as 11 variáveis de DST com 87,76% de respostas) foram consolidadas em uma única coluna _respondido.
  • Redução de redundância — Tabagismo
    Smokes (years) × Smokes (packs/year) combinados em smoke_year_packs (exposição acumulada). Se Smokes=0, os outros campos são zerados.
  • Transformação logarítmica em variáveis demográficas
    log1p aplicado em: Age, Number of sexual partners, First sexual intercourse, Num of pregnancies. Reduz impacto de outliers e normaliza distribuições assimétricas.
  • Feature Engineering — Contraceptivos
    Criadas: contraceptive_mid_risk (uso entre 3–15 anos) e contraceptive_exposure (usa × anos de uso). Se HC=0, anos de uso zerado.
  • Remoção de redundância entre STDs temporais
    STDs: Time since first diagnosis removida — redundância quase perfeita com STDs: Time since last diagnosis (correlação diagonal nos gráficos de dispersão).
  • Criação de atributos estratégicos combinados
    sexual_risk (parceiros/idade), smoke_age_risk, has_std, std_age_risk, combined_risk — combinações que capturam interações não lineares.

Modelagem — Modelos Utilizados e Comparativo

🔬
Estratégia de Experimentação Três cenários progressivos foram testados para superar o recall crítico de 9% do baseline. Todos usam divisão 80% treino / 20% teste com stratify=y e random_state=42, garantindo reprodutibilidade e proporcionalidade das classes (11 positivos nos 172 casos de teste).

Modelo 2 — Random Forest + SMOTE + Threshold 0.41  ⭐ Melhor Resultado
RandomForestClassifier SMOTE · random_state=42 Threshold ajustado: 0.41 Melhor Resultado

O SMOTE (Synthetic Minority Oversampling Technique) gera exemplos sintéticos da classe minoritária no espaço de features, balanceando o treino. O limiar de decisão foi ajustado de 0,50 para 0,41, aumentando o Recall de 9% para 36%. Importante: o SMOTE sozinho piorou o F1 — a combinação SMOTE + class_weight foi o que trouxe o ganho real. 

from imblearn.over_sampling import SMOTE
from sklearn.ensemble import RandomForestClassifier

# Passo de oversampling inserido no Pipeline antes do treino
SMOTE(random_state=42)

# Classificador — SMOTE + class_weight juntos melhoram o F1
RandomForestClassifier(
    class_weight={0: 1, 1: 10},  # penaliza 10× erros na classe positiva
    n_estimators=200,             # 200 árvores na floresta
    min_samples_leaf=1,
    random_state=42
)

# Ajuste do limiar de decisão (padrão = 0.50)
y_proba = pipeline_oversampling.predict_proba(X_test)[:, 1]
threshold = 0.41
y_pred   = (y_proba > threshold).astype(int)
💡
Por que SMOTE + class_weight juntos? O SMOTE balanceia o treino gerando amostras sintéticas; o class_weight ainda penaliza os erros na classe positiva. Testados isoladamente, nenhum trouxe ganho significativo — a combinação foi decisiva para elevar o F1 de 0,15 para 0,33.

Discussão e Conclusões

5.1 — Análise Exploratória

📈
Dataset com pacientes jovens (média 26,8 anos), baixa prevalência de DSTs (10,5%) e tabagismo (14,6%). Mais da metade usa contraceptivos hormonais (64,1%). O desbalanceamento extremo das classes (6,4% positivos) foi o principal desafio. Nenhum atributo isolado apresentou correlação forte com a Biópsia — confirmando a natureza não linear do problema.

5.2 — Estratégias de Pré-processamento

⚙️
A imputação por média combinada com Missing Indicators preservou a informação de não-resposta. O agrupamento de indicadores idênticos reduziu dimensionalidade sem perda de informação. A engenharia de features (smoke_year_packs, contraceptive_exposure, sexual_risk) criou representações mais ricas, com ganho confirmado pela importância de features do Random Forest.

5.4 — Limitações

🚧
Limitações Identificadas
  • Dataset pequeno: 858 registros com apenas 55 positivos limita o aprendizado;
  • SMOTE não é bem visto pela comunidade médica — gera amostras sintéticas, não dados reais;
  • Recall de 36% ainda é inadequado para triagem clínica real (falsos negativos = vidas em risco);
  • Alta taxa de dados faltantes (>91%) nas variáveis temporais de DST reduz seu poder preditivo;
  • Correlações fracas entre features e target — baixo poder preditivo intrínseco do dataset.
⚠️
Conclusão: Dataset sem poder preditivo suficiente para uso clínico Mesmo com técnicas avançadas (SMOTE, ajuste de threshold, GridSearchCV, feature engineering), o melhor AUROC obtido foi 0,737 e o melhor Recall foi 36%. Os resultados são academicamente válidos e demonstram domínio das técnicas, mas não devem ser usados em produção clínica.
💡
O que melhoraria os resultados em um cenário real?
  • Mais dados reais: coletar mais casos positivos confirmados (>500 casos);
  • XGBoost / LightGBM: modelos de boosting tendem a superar RF em datasets pequenos e desbalanceados;
  • Curva Precisão-Recall: mais informativa que AUROC para classes muito desbalanceadas;
  • K-Fold estratificado (k=10): estimativas mais confiáveis com poucos dados;
  • Dados externos: integrar datasets de outros hospitais para ampliar os casos positivos.
